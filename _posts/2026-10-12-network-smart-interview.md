## 四、面试回答通用模板

网络问题建议按这个结构回答：

1. 先给结论。
2. 放到分层模型里说明它在哪一层。
3. 讲关键流程。
4. 讲为什么这样设计。
5. 补充工程场景和常见问题。

示例：

> TCP 是传输层协议，提供面向连接、可靠、有序、字节流传输。它通过序列号、确认应答、超时重传、流量控制和拥塞控制保证可靠性。相比 UDP，TCP 成本更高，但适合文件传输、HTTP 等要求可靠性的场景。

## 五、P0 高频问题清单

### 1. 网络模型

必须会答：

- OSI 七层和 TCP/IP 四层分别是什么？
- 每一层负责什么？
- TCP、IP、HTTP、DNS、ARP 分别在哪一层？
- 数据从应用发送到网卡经过哪些封装？

面试表达重点：

> TCP/IP 更贴近实际工程。应用层负责应用协议，如 HTTP、DNS；传输层负责端到端传输，如 TCP/UDP；网络层负责 IP 寻址和路由；网络接口层负责局域网内传输和 MAC 寻址。发送数据时会逐层封装，接收时逐层解封装。

### 2. 输入 URL 到页面展示

必须会答：

- 输入 URL 后发生了什么？
- DNS 查询过程是什么？
- TCP 和 TLS 在哪里发生？
- HTTP 请求和响应之后浏览器如何渲染？

面试表达重点：

> 流程可以概括为：解析 URL、检查缓存、DNS 解析得到 IP、建立 TCP 连接、HTTPS 场景进行 TLS 握手、发送 HTTP 请求、服务器处理并返回响应、浏览器解析 HTML/CSS/JS 并渲染页面，最后根据连接策略复用或关闭连接。

### 3. HTTP 报文、方法和状态码

必须会答：

- HTTP 请求报文和响应报文结构？
- GET 和 POST 区别？
- 常见状态码有哪些？
- 301 和 302 区别？401 和 403 区别？502 和 504 区别？

面试表达重点：

> HTTP 请求由请求行、请求头、空行、请求体组成；响应由状态行、响应头、空行、响应体组成。GET 通常用于获取资源，参数常放 URL，具备幂等语义；POST 通常用于提交数据，请求体承载数据，一般不要求幂等。

常见状态码速记：

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 304 | 协商缓存命中 |
| 400 | 请求错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务端错误 |
| 502 | 网关收到上游错误响应 |
| 504 | 网关等待上游超时 |

### 4. HTTP 版本

必须会答：

- HTTP/1.0 和 HTTP/1.1 区别？
- HTTP/1.1 和 HTTP/2 区别？
- HTTP/3 为什么基于 QUIC？

面试表达重点：

> HTTP/1.1 相比 1.0 引入长连接、管线化和更完善的缓存控制。HTTP/2 使用二进制分帧、多路复用、头部压缩，缓解队头阻塞。HTTP/3 基于 QUIC 和 UDP，把连接管理、可靠传输、拥塞控制放到用户态，减少 TCP 层队头阻塞并优化握手时延。

### 5. HTTP 缓存

必须会答：

- 强缓存和协商缓存区别？
- Cache-Control、Expires、ETag、Last-Modified 分别是什么？
- 304 是什么意思？

面试表达重点：

> 强缓存命中时不需要请求服务器，常由 Cache-Control 或 Expires 控制；协商缓存需要向服务器验证资源是否变化，常用 ETag/If-None-Match 或 Last-Modified/If-Modified-Since。服务器返回 304 表示资源未变化，客户端继续使用本地缓存。

### 6. Cookie 和 Session

必须会答：

- Cookie 和 Session 区别？
- Cookie 工作原理？
- Session 如何识别用户？
- Token 和 Session 有什么不同？

面试表达重点：

> Cookie 存在客户端，每次请求可自动携带；Session 存在服务端，客户端通常通过 Cookie 中的 session id 关联服务端状态。Cookie 适合保存少量非敏感标识，Session 适合保存服务端会话状态。

### 7. HTTPS 和 TLS

必须会答：

- HTTP 和 HTTPS 区别？
- HTTPS 如何保证安全？
- TLS 握手过程是什么？
- 为什么既用非对称加密又用对称加密？
- 证书解决什么问题？

面试表达重点：

> HTTPS = HTTP + TLS。TLS 主要提供身份认证、数据加密和完整性保护。非对称加密用于身份认证和安全协商密钥，对称加密用于后续大量数据传输，因为效率更高。证书用于证明服务端公钥的可信性，避免中间人伪造。

### 8. TCP 和 UDP

必须会答：

- TCP 和 UDP 区别？
- TCP 如何保证可靠传输？
- UDP 适合什么场景？
- 如何基于 UDP 实现可靠传输？

面试表达重点：

> TCP 面向连接、可靠、有序、字节流，有流量控制和拥塞控制；UDP 无连接、不保证可靠和有序，但开销小、时延低，适合音视频、游戏、DNS 等场景。如果要可靠 UDP，需要在应用层实现序列号、ACK、重传、去重、排序和拥塞控制。

### 9. 三次握手

必须会答：

- 三次握手过程？
- 为什么不是两次？
- SYN 洪泛是什么？
- 初始序列号有什么作用？

面试表达重点：

> 三次握手的核心是双方确认彼此的发送和接收能力，并同步初始序列号。两次握手无法让客户端确认服务端的发送能力，也容易让历史连接请求导致服务端建立无效连接。

### 10. 四次挥手和 TIME_WAIT

必须会答：

- 四次挥手过程？
- 为什么挥手通常需要四次？
- TIME_WAIT 为什么存在？
- TIME_WAIT 过多怎么办？

面试表达重点：

> TCP 是全双工连接，关闭时双方发送方向需要分别关闭，所以通常需要四次挥手。TIME_WAIT 的作用是确保最后一个 ACK 能被对方收到，并让旧连接中的迟到报文在网络中消失，避免影响新连接。

### 11. 流量控制和拥塞控制

必须会答：

- 流量控制解决什么问题？
- 拥塞控制解决什么问题？
- 滑动窗口是什么？
- 慢启动、拥塞避免、快重传、快恢复是什么？

面试表达重点：

> 流量控制关注接收方是否来得及接收，通过接收窗口限制发送速度；拥塞控制关注网络是否承载得住，通过拥塞窗口动态调整发送速率。TCP 实际发送窗口通常取接收窗口和拥塞窗口的较小值。

### 12. 粘包和拆包

必须会答：

- TCP 为什么会粘包？
- UDP 会不会粘包？
- 如何解决粘包和拆包？

面试表达重点：

> TCP 是面向字节流的协议，没有消息边界，应用层多次写入的数据可能被合并发送，一次写入的数据也可能被拆分接收。解决方法是在应用层设计协议边界，比如固定长度、分隔符、长度字段、TLV 格式等。

## 六、网络排查表达

| 问题 | 排查思路 |
|---|---|
| 访问慢 | DNS、TCP 建连、TLS、服务端处理、响应体大小、丢包重传 |
| 连接失败 | 域名解析、路由、防火墙、端口监听、三次握手状态 |
| 偶发超时 | 网络抖动、拥塞、服务端负载、连接池耗尽、重传 |
| HTTPS 失败 | 证书过期、域名不匹配、TLS 版本/加密套件不兼容 |
| TIME_WAIT 多 | 主动关闭连接多、短连接多、连接复用不足 |
| 粘包问题 | 应用层协议无边界，检查长度字段和解包逻辑 |

## 九、按优先级整理的面试答案库

这一节按 P0、P1、P2 排列，先掌握网络传输主线和 HTTP/TCP 高频问题，再补充 DNS、CDN、NAT、HTTP/3 等进阶内容。

## P0：必须优先掌握

### 1. OSI 七层和 TCP/IP 四层分别是什么？

OSI 七层：

| 层级 | 作用 |
|---|---|
| 应用层 | 为应用程序提供网络服务 |
| 表示层 | 数据格式转换、加密、压缩 |
| 会话层 | 建立、管理、终止会话 |
| 传输层 | 端到端传输，如 TCP/UDP |
| 网络层 | IP 寻址、路由转发 |
| 数据链路层 | 帧传输、MAC 地址、差错检测 |
| 物理层 | 比特流传输 |

TCP/IP 四层：

| 层级 | 协议示例 |
|---|---|
| 应用层 | HTTP、DNS、FTP、SMTP |
| 传输层 | TCP、UDP |
| 网络层 | IP、ICMP |
| 网络接口层 | Ethernet、ARP、Wi-Fi |

面试表达：

> OSI 更偏理论分层，TCP/IP 更贴近实际工程。实际排查问题时，可以按应用层、传输层、网络层、链路层逐层定位。

### 2. TCP、IP、HTTP、DNS、ARP 分别在哪一层？

| 协议 | 所在层 |
|---|---|
| HTTP | 应用层 |
| DNS | 应用层 |
| TCP | 传输层 |
| UDP | 传输层 |
| IP | 网络层 |
| ICMP | 网络层 |
| ARP | 网络接口层/链路层附近，用于 IP 到 MAC 的解析 |

面试表达：

> HTTP 解决应用数据格式，TCP 解决可靠端到端传输，IP 解决跨网络寻址和路由，ARP 解决局域网内下一跳 MAC 地址获取。

### 3. 输入 URL 到页面展示发生了什么？

核心流程：

1. 浏览器解析 URL，得到协议、域名、端口、路径。
2. 检查浏览器缓存，命中强缓存则直接使用。
3. DNS 解析域名得到 IP。
4. 建立 TCP 连接，经历三次握手。
5. 如果是 HTTPS，进行 TLS 握手，协商密钥并验证证书。
6. 浏览器发送 HTTP 请求。
7. 服务端处理请求并返回 HTTP 响应。
8. 浏览器解析 HTML，构建 DOM。
9. 解析 CSS 构建 CSSOM，合成渲染树。
10. 布局、绘制、合成，展示页面。
11. 根据协议和连接头决定复用或关闭连接。

面试表达：

> 这个问题要按链路讲：先应用层 URL 和缓存，再 DNS，再 TCP/TLS 建连，再 HTTP 请求响应，最后浏览器渲染。

### 4. DNS 查询过程是什么？

常见查询链路：

1. 浏览器缓存
2. 操作系统缓存和 hosts 文件
3. 本地 DNS 服务器
4. 根 DNS 服务器
5. 顶级域 DNS 服务器
6. 权威 DNS 服务器
7. 返回 IP 并缓存结果

面试表达：

> DNS 的作用是把域名解析成 IP。为了性能，浏览器、系统、本地 DNS 都会缓存结果。DNS 慢或解析错误会直接影响首包时间和连接成功率。

### 5. HTTP 请求报文和响应报文结构是什么？

HTTP 请求报文：

```text
请求行：方法 URL HTTP版本
请求头：Host、User-Agent、Content-Type、Cookie 等
空行
请求体：POST/PUT 等请求携带的数据
```

HTTP 响应报文：

```text
状态行：HTTP版本 状态码 状态描述
响应头：Content-Type、Content-Length、Cache-Control、Set-Cookie 等
空行
响应体：HTML/JSON/图片等资源
```

面试表达：

> 请求报文描述客户端要什么，响应报文描述服务端处理结果和返回内容。状态码、缓存、Cookie、内容类型都通过头部表达。

### 6. GET 和 POST 有什么区别？

| 对比项 | GET | POST |
|---|---|---|
| 语义 | 获取资源 | 提交数据或创建资源 |
| 参数位置 | 常见于 URL query | 常见于请求体 |
| 幂等性 | 通常幂等 | 通常不保证幂等 |
| 缓存 | 更容易被缓存 | 通常不缓存 |
| 数据大小 | 受 URL 长度限制 | 理论上主要受服务端配置限制 |

面试表达：

> GET 和 POST 的核心区别不是“谁更安全”，而是语义不同。GET 用于获取资源，应该不改变服务端状态；POST 用于提交数据，可能改变服务端状态。HTTPS 下两者传输都会被加密，但 GET 参数会出现在 URL，更容易被日志、历史记录保存。

### 7. 常见 HTTP 状态码有哪些？

| 状态码 | 含义 |
|---|---|
| 200 | 请求成功 |
| 201 | 创建成功 |
| 204 | 成功但无响应体 |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 304 | 协商缓存命中 |
| 400 | 请求格式错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务端内部错误 |
| 502 | 网关收到上游错误响应 |
| 503 | 服务暂不可用 |
| 504 | 网关等待上游超时 |

面试表达：

> 2xx 表示成功，3xx 表示重定向或缓存，4xx 表示客户端请求问题，5xx 表示服务端或网关问题。

### 8. HTTP/1.0、HTTP/1.1、HTTP/2、HTTP/3 有什么区别？

| 版本 | 关键点 |
|---|---|
| HTTP/1.0 | 默认短连接，每个请求通常新建连接 |
| HTTP/1.1 | 默认长连接，支持 Host、缓存增强、管线化 |
| HTTP/2 | 二进制分帧、多路复用、头部压缩、服务端推送 |
| HTTP/3 | 基于 QUIC/UDP，减少 TCP 队头阻塞，优化握手 |

面试表达：

> HTTP/1.1 主要解决连接复用问题，HTTP/2 通过多路复用提升单连接并发能力，HTTP/3 进一步把传输层能力放到 QUIC 中，减少 TCP 层队头阻塞和握手时延。

### 9. HTTP 和 HTTPS 有什么区别？

HTTP 明文传输，默认端口 80；HTTPS 在 HTTP 和 TCP 之间加入 TLS，默认端口 443，提供加密、身份认证和完整性保护。

面试表达：

> HTTPS 不是新的应用层语义，而是 HTTP over TLS。它解决三类问题：防窃听、防篡改、防伪造。

### 10. HTTPS 为什么既用非对称加密又用对称加密？

非对称加密适合身份认证和密钥协商，但计算成本高；对称加密速度快，适合大量业务数据传输。

面试表达：

> TLS 握手阶段用非对称加密和证书验证服务端身份，并安全协商会话密钥；后续数据传输用对称加密，提高性能。

### 11. TLS 握手大致过程是什么？

简化流程：

1. 客户端发送支持的 TLS 版本、随机数、加密套件。
2. 服务端返回选择的加密套件、随机数和证书。
3. 客户端验证证书是否合法。
4. 双方协商或生成会话密钥。
5. 后续使用对称密钥加密通信。

面试表达：

> TLS 握手的核心是验证服务端身份，并让双方安全地得到同一个会话密钥。

### 12. 强缓存和协商缓存有什么区别？

强缓存命中时，浏览器不请求服务器，直接使用本地缓存；协商缓存需要向服务器发送请求，由服务器判断资源是否变化。

| 缓存 | 相关头 |
|---|---|
| 强缓存 | `Cache-Control`、`Expires` |
| 协商缓存 | `ETag`/`If-None-Match`、`Last-Modified`/`If-Modified-Since` |

面试表达：

> 强缓存减少网络请求，协商缓存减少响应体传输。返回 304 表示资源未修改，客户端继续使用本地缓存。

### 13. Cookie 和 Session 有什么区别？

Cookie 存储在客户端，请求时可自动携带；Session 存储在服务端，客户端通常通过 Cookie 中的 session id 关联服务端会话。

面试表达：

> Cookie 适合保存少量状态标识，但不要保存敏感明文。Session 安全性和可控性更好，但服务端需要存储和管理会话状态，分布式环境下要考虑共享或集中存储。

### 14. TCP 和 UDP 有什么区别？

| 对比项 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠、有序、不丢不重 | 不保证可靠 |
| 数据形式 | 字节流 | 数据报 |
| 控制机制 | 流量控制、拥塞控制 | 无内置控制 |
| 开销 | 较高 | 较低 |
| 场景 | HTTP、文件传输、可靠通信 | DNS、音视频、游戏、实时通信 |

面试表达：

> TCP 用复杂机制换可靠性，UDP 用简单机制换低延迟和低开销。选择哪个取决于业务更看重可靠性还是实时性。

### 15. TCP 如何保证可靠传输？

TCP 通过这些机制保证可靠：

- 序列号：标识字节顺序
- 确认应答 ACK：确认收到的数据
- 超时重传：未收到 ACK 时重发
- 快重传：收到重复 ACK 时尽快重传
- 校验和：检测数据错误
- 滑动窗口：控制发送和确认范围
- 流量控制：避免压垮接收方
- 拥塞控制：避免压垮网络

面试表达：

> TCP 的可靠性不是靠单一机制，而是序列号、ACK、重传、窗口和拥塞控制共同保证。

### 16. 三次握手过程是什么？为什么不是两次？

过程：

1. 客户端发送 SYN，进入 SYN_SENT。
2. 服务端收到后返回 SYN+ACK，进入 SYN_RCVD。
3. 客户端发送 ACK，双方进入 ESTABLISHED。

为什么不是两次：

> 三次握手能让双方都确认彼此的发送和接收能力，并同步初始序列号。两次握手时，服务端无法确认客户端是否收到了自己的 SYN+ACK，也容易因为历史重复 SYN 导致无效连接。

### 17. 四次挥手过程是什么？为什么通常需要四次？

过程：

1. 主动关闭方发送 FIN。
2. 被动关闭方回复 ACK。
3. 被动关闭方数据发送完后发送 FIN。
4. 主动关闭方回复 ACK，进入 TIME_WAIT。

为什么四次：

> TCP 是全双工连接，两个方向需要分别关闭。收到 FIN 只表示对方不再发送数据，但自己可能还有数据要发，所以 ACK 和 FIN 通常分开发送。

### 18. TIME_WAIT 为什么存在？

作用：

1. 确保最后一个 ACK 能被对方收到。如果 ACK 丢失，对方会重发 FIN。
2. 等待旧连接中的迟到报文在网络中消失，避免影响相同四元组的新连接。

面试表达：

> TIME_WAIT 是 TCP 正确关闭连接的安全机制，不是单纯浪费资源。过多时要分析是否大量短连接、主动关闭过多或连接复用不足。

## P1：传输层进阶和工程常问

### 19. 流量控制和拥塞控制有什么区别？

流量控制保护接收方，避免发送方发太快导致接收缓冲区溢出；拥塞控制保护网络，避免过多数据进入网络导致拥塞。

| 机制 | 关注对象 | 核心变量 |
|---|---|---|
| 流量控制 | 接收方能力 | 接收窗口 rwnd |
| 拥塞控制 | 网络承载能力 | 拥塞窗口 cwnd |

面试表达：

> TCP 实际可发送窗口通常取接收窗口和拥塞窗口的较小值。

### 20. 拥塞控制有哪些阶段？

常见阶段：

- 慢启动：拥塞窗口指数增长
- 拥塞避免：达到阈值后线性增长
- 快重传：收到多个重复 ACK 后立即重传
- 快恢复：避免直接回到慢启动，降低窗口后继续传输

面试表达：

> 拥塞控制的目标是在充分利用网络和避免拥塞崩溃之间取得平衡。

### 21. TCP 粘包和拆包是什么？如何解决？

TCP 是面向字节流的协议，没有消息边界。发送方多次写入可能被接收方一次读到，这叫粘包；一次写入可能被多次读到，这叫拆包。

解决方法：

- 固定长度消息
- 特殊分隔符
- 消息头中带长度字段
- TLV 协议格式

面试表达：

> 粘包不是 TCP 错误，而是字节流语义决定的。应用层协议必须自己定义消息边界。

### 22. HTTP Keep-Alive 和 TCP Keepalive 有什么区别？

HTTP Keep-Alive 是应用层连接复用机制，让多个 HTTP 请求复用同一个 TCP 连接；TCP Keepalive 是传输层保活探测机制，用来检测连接是否还活着。

面试表达：

> 一个是为了复用连接、减少建连成本；一个是为了探测死连接。

### 23. 如何实现可靠 UDP？

需要在应用层补 TCP 类似机制：

- 序列号
- ACK 确认
- 超时重传
- 去重
- 排序
- 滑动窗口
- 拥塞控制

面试表达：

> 可靠 UDP 不是简单“UDP 加重传”，还要处理乱序、重复、丢包、拥塞和延迟之间的取舍。QUIC 就是在 UDP 之上实现了可靠传输和连接管理。

### 24. TIME_WAIT 过多怎么办？

先分析原因：

- 大量短连接
- 本端主动关闭连接多
- 连接池没有复用
- 上游/下游异常导致频繁重连

优化方向：

- 使用连接池和长连接
- 开启 HTTP Keep-Alive
- 调整系统参数要谨慎
- 优化服务端主动关闭策略
- 排查异常重连

面试表达：

> 不能一看到 TIME_WAIT 多就粗暴改内核参数，先判断是不是业务短连接或连接复用不足导致。

## P2：补充广度和新协议

### 25. CDN 是什么？有什么作用？

CDN 是内容分发网络，通过把静态资源缓存到离用户更近的边缘节点，降低访问延迟和源站压力。

作用：

- 加速静态资源访问
- 降低源站带宽压力
- 提高可用性
- 就近访问

面试表达：

> CDN 的核心是缓存和调度。用户访问资源时，DNS 或调度系统会把请求导向较近或较优的边缘节点。

### 26. NAT 解决什么问题？

NAT 网络地址转换主要解决内网私有地址访问公网的问题，也缓解 IPv4 地址不足。

面试表达：

> NAT 会把内网 IP:端口 映射成公网 IP:端口。它隐藏了内网结构，但也让端到端连接变复杂，比如 P2P、部分实时通信需要 NAT 穿透。

### 27. ping 的原理是什么？

ping 基于 ICMP 协议。发送 ICMP Echo Request，目标主机收到后返回 ICMP Echo Reply，通过往返时间和丢包情况判断网络连通性。

面试表达：

> ping 能证明网络层连通性，但 ping 通不代表 TCP 端口可用；ping 不通也不一定代表服务不可用，可能是 ICMP 被防火墙禁用。

### 28. HTTP/3 和 QUIC 有什么特点？

QUIC 基于 UDP，在用户态实现连接管理、可靠传输、拥塞控制和加密。HTTP/3 基于 QUIC。

优点：

- 减少握手时延
- 避免 TCP 层队头阻塞
- 连接迁移能力更好
- TLS 1.3 深度集成

面试表达：

> HTTP/3 不是简单把 HTTP 放到 UDP 上，而是基于 QUIC 重新实现了很多传输层能力。

### 29. 访问一个网站很慢，如何排查？

按链路排查：

1. DNS 是否慢或解析错误。
2. TCP 建连是否慢，是否丢包重传。
3. TLS 握手是否慢，证书是否异常。
4. 服务端处理是否慢。
5. 响应体是否过大。
6. CDN 是否命中。
7. 客户端渲染是否慢。

面试表达：

> 网络慢不能只看一个点，要拆成 DNS、建连、TLS、请求处理、下载、渲染几个阶段，分别用日志、抓包、浏览器开发者工具或监控指标验证。
