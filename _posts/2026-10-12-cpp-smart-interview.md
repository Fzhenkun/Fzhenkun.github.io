## 三、C++11/14/17/20 特性知识清单

面试时不要只背“新增了什么”，还要能说明特性解决的问题、适用场景、生命周期或性能影响，以及使用时的边界。下面按标准版本整理，复习时逐项勾选。

### C++11：现代 C++ 的基础

- [ ] `auto`、`decltype`：类型推导规则，引用、`const` 和表达式类型的差异
- [ ] `nullptr`：区别于 `NULL` 和 `0`，避免重载调用歧义
- [ ] 范围 `for`：遍历副本、引用和 `const` 引用的区别
- [ ] 初始化列表和统一初始化：防止窄化转换，理解 `std::initializer_list` 的优先匹配
- [ ] `enum class`：强类型枚举和作用域隔离
- [ ] `using` 类型别名：与 `typedef` 的区别，以及模板别名
- [ ] `constexpr`：编译期求值与运行期求值的区别，`const` 与 `constexpr` 的区别
- [ ] `static_assert`：编译期检查模板参数或类型约束
- [ ] Lambda：捕获列表、值捕获与引用捕获、可变 Lambda、返回类型和生命周期风险
- [ ] 右值引用、移动构造、移动赋值和完美转发：`std::move`/`std::forward` 的作用
- [ ] 特殊成员函数规则：拷贝/移动构造和赋值运算符的隐式生成、`= default`、`= delete`

- [ ] `std::array`、`std::unordered_map`、`std::tuple`、`std::function`、`std::bind`
- [ ] 正则表达式、随机数库、时间库和文件流的基本使用场景

### C++14：让 C++11 更易用

- [ ] 泛型 Lambda：`[](const auto& value) { ... }` 的类型推导

- [ ] 放宽 `constexpr` 函数限制：允许局部变量和多条语句
- [ ] 函数返回类型推导：`auto f() { return value; }` 的限制
- [ ] `std::make_unique`：异常安全地创建 `unique_ptr`
- [ ] 二进制字面量和数字分隔符：提升常量可读性

### C++17：更强的类型推导与库能力

- [ ] 结构化绑定：解包 `pair`、`tuple`、数组和可绑定对象时的引用/值语义
- [ ] `if constexpr`：编译期分支，解决模板代码中的类型分支问题
- [ ] `constexpr` Lambda、`constexpr` 更宽松的限制
- [ ] 类模板参数推导（CTAD）：何时能省略模板参数，何时需要显式指定
- [ ] `inline` 变量：头文件中定义全局变量或静态成员的 ODR 问题
- [ ] `std::optional`：表达“可能没有值”，与指针、异常的取舍
- [ ] `std::variant` 和 `std::visit`：类型安全的联合体和访问方式
- [ ] `std::any`：运行期保存任意类型，了解类型擦除和性能成本
- [ ] `std::string_view`：非拥有视图、生命周期悬空和不保证以 `\0` 结尾
- [ ] `std::filesystem`：路径、文件和目录操作

## 五、面试回答通用模板

遇到 C++ 问题，不要一上来散讲。用这个结构：

1. 先给结论：它是什么，核心区别是什么。
2. 再讲原理：底层机制、生命周期、内存位置、编译/运行期行为。
3. 然后讲场景：什么时候用，什么时候不用。
4. 最后讲坑点：常见错误、性能影响、项目中如何避免。

示例：

> 指针和引用的区别：指针是变量，保存地址，可以为空，也可以改变指向；引用是对象别名，声明时必须初始化，通常不能重新绑定。工程上如果参数必然存在，优先用引用表达非空语义；如果参数可能为空、需要改变指向或表达所有权关系，则用指针。常见坑是空指针、野指针、悬空指针，这些都可能导致崩溃。

## 六、P0 高频问题清单

### 1. 指针和引用

必须会答：

- 指针和引用的区别是什么？
- 函数参数什么时候用指针，什么时候用引用？
- 野指针和悬空指针有什么区别？
- 空指针和空引用有什么区别？

面试表达重点：

> 指针强调地址和可空性，引用强调别名和非空语义。项目中如果接口参数必须有效，我会优先用引用；如果有可选对象、数组遍历、所有权转移或底层内存操作，就用指针或智能指针。

### 2. const 和 static

必须会答：

- const 修饰变量、指针、成员函数分别表示什么？
- 常量指针和指针常量怎么区分？
- static 修饰局部变量、全局变量、成员变量、成员函数分别有什么作用？

面试表达重点：

> const 主要表达不可修改语义，static 主要影响生命周期、作用域和归属关系。static 局部变量生命周期贯穿整个程序，但作用域仍在函数内；static 全局变量限制在当前文件；static 成员属于类，不属于对象。

### 3. 编译链接和内存分区

必须会答：

- 编译链接过程分几步？
- 栈、堆、全局/静态区、常量区、代码区分别存什么？
- 堆和栈有什么区别？
- malloc 分配的是物理内存还是虚拟内存？

面试表达重点：

> C++ 程序从源码到可执行文件通常经过预处理、编译、汇编、链接。运行后进程拥有虚拟地址空间，不同区域用于存放代码、全局变量、堆、栈等。理解这些有助于分析栈溢出、内存泄漏、越界访问等问题。

### 4. new/delete 和 malloc/free

必须会答：

- new 和 malloc 的区别？
- delete 和 free 的区别？
- new 可以重载吗？用在哪里？
- 只 malloc 不 free 会怎样？

面试表达重点：

> malloc/free 是 C 库函数，只负责申请和释放原始内存；new/delete 是 C++ 运算符，除了内存分配，还会调用构造和析构。对象资源管理要优先用 RAII 和智能指针，减少手动释放带来的泄漏和悬空指针。

### 5. 面向对象和虚函数

必须会答：

- 封装、继承、多态分别是什么？
- C++ 多态如何实现？
- 虚函数表和虚函数指针是什么？
- 析构函数为什么常常要设为 virtual？
- 构造函数能不能是虚函数？析构函数能不能是虚函数？

面试表达重点：

> C++ 运行时多态主要依赖虚函数表。通过基类指针或引用调用虚函数时，会根据对象实际类型进行动态绑定。基类析构函数通常要设为 virtual，否则通过基类指针删除派生类对象时，可能只调用基类析构，导致派生类资源泄漏。

### 6. 深拷贝、浅拷贝和 RAII

必须会答：

- 深拷贝和浅拷贝区别？
- 什么情况下需要自定义拷贝构造和赋值运算符？
- RAII 是什么？
- 为什么 RAII 能减少资源泄漏？

面试表达重点：

> 如果类内部管理堆内存、文件句柄、锁、socket 等资源，默认浅拷贝可能导致多个对象指向同一资源，进而产生重复释放或悬空指针。RAII 的核心是把资源生命周期绑定到对象生命周期，构造时获取资源，析构时释放资源。

### 7. 智能指针

必须会答：

- unique_ptr、shared_ptr、weak_ptr 区别？
- shared_ptr 的引用计数原理？
- weak_ptr 解决什么问题？
- 什么是 shared_ptr 循环引用？如何解决？
- shared_ptr 是线程安全的吗？

面试表达重点：

> unique_ptr 表达独占所有权，不能拷贝但可以移动；shared_ptr 表达共享所有权，通过引用计数释放资源；weak_ptr 不增加引用计数，主要用于观察对象和解决 shared_ptr 循环引用。shared_ptr 的引用计数增减通常是线程安全的，但其管理对象本身的访问不是天然线程安全。

### 8. 移动语义和右值引用

必须会答：

- 左值和右值是什么？
- 右值引用解决什么问题？
- std::move 做了什么？
- 移动构造和拷贝构造有什么区别？

面试表达重点：

> 移动语义的目标是避免不必要的深拷贝，把临时对象或不再使用对象中的资源转移出去。std::move 本身不移动资源，只是把对象强制转换成右值引用，真正的资源转移发生在移动构造或移动赋值中。

### 9. STL 容器

必须会答：

- vector 和 list 区别？
- map 和 unordered_map 区别？
- vector 扩容机制是什么？
- 迭代器失效场景有哪些？

面试表达重点：

> vector 底层连续内存，随机访问快，尾插通常高效，但扩容会迁移元素并导致迭代器失效；list 是链表，插入删除稳定但缓存局部性差。map 通常是红黑树，有序，查找 O(logN)；unordered_map 是哈希表，平均 O(1)，但无序且受哈希冲突影响。

### 10. 多线程

必须会答：

- 什么是线程安全？
- mutex 和 condition_variable 如何配合？
- 什么是死锁？如何避免？
- 线程池的基本结构是什么？

面试表达重点：

> 多线程问题的本质是共享数据访问顺序不可控。常见手段是互斥锁保护临界区，条件变量负责线程间等待和唤醒。避免死锁可以从固定加锁顺序、减少锁粒度、使用 RAII 锁、超时和 try_lock 等角度入手。

## 十、按优先级整理的面试答案库

## P0：必须优先掌握

### 1. 指针和引用有什么区别？

指针本质是一个变量，保存另一个对象的地址，可以为空，也可以改变指向；引用是已有对象的别名，声明时必须初始化，通常不能重新绑定。

面试回答可以这样说：

> 指针强调地址和可空性，适合表达“可能为空”“需要改变指向”“需要操作底层内存”的场景。引用强调别名和非空语义，适合函数参数传递、避免拷贝、表达参数必须有效的场景。工程上我会优先用引用表达非空输入，用指针或智能指针表达可空、所有权或生命周期关系。

### 2. 函数参数什么时候用指针，什么时候用引用？

如果参数一定存在，不需要表达空值，通常用引用；如果参数可能为空、需要在函数内部修改指向、需要表达可选对象或所有权关系，可以用指针。

常见表达：

> 只读大对象用 `const T&`，需要修改对象内容用 `T&`。如果参数可能不存在，用 `T*` 或智能指针。如果涉及资源所有权转移，用 `std::unique_ptr`；如果多个对象共享生命周期，用 `std::shared_ptr`，但要避免滥用。

### 3. 野指针和悬空指针有什么区别？

野指针通常指未初始化的指针，指向未知地址；悬空指针指曾经指向有效对象，但对象已经释放或生命周期结束，指针还保留旧地址。

工程风险：

> 两者解引用都可能导致未定义行为，常见结果是崩溃、数据破坏、偶发问题。避免方式是初始化为 `nullptr`，释放后置空，减少裸指针所有权，用 RAII 和智能指针管理资源。

### 4. const 的作用是什么？

`const` 用来表达不可修改语义，可以修饰变量、指针、引用、函数参数、返回值和成员函数。

重点区分：

```cpp
const int* p;      // 指向常量的指针，不能通过 p 修改 *p，但 p 可以改指向
int* const p;      // 常量指针，p 不能改指向，但可以修改 *p
const int* const p;// 指向常量的常量指针
```

成员函数后面的 `const` 表示不修改对象的逻辑状态：

```cpp
int size() const;
```

面试表达：

> const 不只是语法限制，也是一种接口契约。它能告诉调用方这个函数不会修改对象状态，也能帮助编译器发现误修改。

### 5. static 的作用是什么？

`static` 的核心作用是控制生命周期、作用域和归属关系。

| 场景 | 含义 |
|---|---|
| static 局部变量 | 生命周期贯穿程序运行期，但作用域只在函数内 |
| static 全局变量 | 限制在当前源文件内可见，属于内部链接 |
| static 全局函数 | 只在当前源文件内可见，避免命名冲突 |
| static 成员变量 | 属于类，不属于某个对象，所有对象共享 |
| static 成员函数 | 属于类，没有 `this` 指针，只能直接访问静态成员 |

面试表达：

> static 局部变量常用于需要跨函数调用保留状态的场景；static 全局变量和函数常用于限制文件作用域，减少外部可见性；static 成员用于表达类级别共享状态。

### 6. 编译链接过程是什么？

通常分为四步：

| 阶段 | 作用 |
|---|---|
| 预处理 | 展开头文件、宏替换、条件编译，生成预处理结果 |
| 编译 | 进行语法语义分析，生成汇编代码 |
| 汇编 | 把汇编代码转换成目标文件 |
| 链接 | 合并目标文件和库，解析符号引用，生成可执行文件 |

面试表达：

> 编译阶段关注单个源文件是否合法，链接阶段关注多个目标文件之间的符号能否对上。常见的“undefined reference”或“无法解析的外部符号”通常是链接阶段问题。

### 7. C++ 程序内存分区有哪些？

常见划分：

| 区域 | 存放内容 |
|---|---|
| 代码区 | 程序机器指令 |
| 只读常量区 | 字符串字面量、部分常量 |
| 全局/静态区 | 全局变量、静态变量 |
| 堆 | 动态分配内存，如 `new`、`malloc` |
| 内存映射 | 共享库、匿名映射、文件映射、设备映射 |
| 栈 | 函数调用帧、局部变量、返回地址、参数等 |

面试表达：

> 理解内存分区有助于分析栈溢出、内存泄漏、越界访问和对象生命周期问题。比如局部大数组可能导致栈溢出，堆对象忘记释放会导致内存泄漏。
> 内存映射：
> 共享库区：动态链接库（.so/.dll）映射区，可被多个进程共享。
> 匿名映射区：mmap创建的匿名内存映射，用于共享内存或临时数据。
> 设备映射区：映射硬件设备寄存器。
> 内存映射文件区：映射磁盘文件到进程地址空间。

### 8. 堆和栈有什么区别？

栈由系统自动管理，函数调用时分配，返回时释放，速度快但空间相对有限；堆由程序动态申请和释放，空间更灵活，但需要管理生命周期，容易产生泄漏和碎片。

面试表达：

> 栈适合生命周期明确、较小的局部对象；堆适合生命周期跨作用域、运行期确定或较大的对象。C++ 中应优先用 RAII 对堆资源进行封装。

### 9. new/delete 和 malloc/free 有什么区别？

`malloc/free` 是 C 标准库函数，只负责分配和释放原始内存；`new/delete` 是 C++ 运算符，除了分配/释放内存，还会调用构造函数和析构函数。

| 对比项 | new/delete | malloc/free |
|---|---|---|
| 类型 | C++ 运算符 | C 库函数 |
| 构造析构 | 会调用 | 不会调用 |
| 返回类型 | 具体类型指针 | `void*` |
| 失败行为 | 默认抛出异常 | 返回 `NULL` |
| 可重载 | 可以 | 不可以像运算符那样重载 |

面试表达：

> C++ 对象应使用 new/delete 或更推荐使用智能指针、容器和 RAII。malloc 只适合申请原始内存，不会构造对象。

### 10. 什么是内存泄漏？如何避免？

内存泄漏是指动态申请的内存不再使用，但没有释放，程序也失去了访问它的途径，导致内存持续增长。

常见原因：

- `new/malloc` 后没有 `delete/free`
- 异常路径提前返回导致释放逻辑未执行
- shared_ptr 循环引用
- 缓存无限增长
- 对象生命周期设计混乱

避免方式：

> 优先使用 RAII、智能指针和 STL 容器；明确资源所有权；释放路径要覆盖异常和提前返回；shared_ptr 循环引用用 weak_ptr 打破；对缓存设置容量和淘汰策略。

### 11. 什么是 RAII？

RAII 是 Resource Acquisition Is Initialization，资源获取即初始化。核心思想是把资源生命周期绑定到对象生命周期：构造函数中获取资源，析构函数中释放资源。

典型例子：

- `std::unique_ptr` 管理堆对象
- `std::lock_guard` 管理互斥锁
- 文件对象析构时关闭文件句柄

面试表达：

> RAII 能把资源释放从“手动记得做”变成“对象生命周期自动保证”，可以显著减少内存泄漏、锁未释放、句柄泄漏等问题。

### 12. 深拷贝和浅拷贝有什么区别？

浅拷贝只复制对象的成员值，如果成员里有指针，就只复制地址，多个对象会指向同一块资源；深拷贝会重新分配资源并复制资源内容，使对象之间拥有独立资源。

风险：

> 如果类管理堆内存、文件句柄、socket 等资源，默认浅拷贝可能导致重复释放、悬空指针、数据互相影响。此时要自定义拷贝构造、赋值运算符，或者禁止拷贝，或者使用智能指针/容器管理资源。

### 13. C++ 多态如何实现？

C++ 运行时多态主要通过虚函数实现。含有虚函数的类对象中通常有虚表指针，指向虚函数表；虚函数表中保存虚函数地址。通过基类指针或引用调用虚函数时，会根据对象实际类型进行动态绑定。

面试表达：

> 多态的价值是用统一的基类接口调用不同派生类实现，降低调用方和具体类型的耦合。代价是多一次间接调用，并且对象通常需要保存虚表指针。

### 14. 析构函数为什么常常要设为 virtual？

如果通过基类指针删除派生类对象，而基类析构函数不是虚函数，可能只调用基类析构，不调用派生类析构，导致派生类资源泄漏。

示例：

```cpp
Base* p = new Derived();
delete p; // Base 析构非 virtual 时，Derived 析构可能不被调用
```

面试表达：

> 只要一个类被设计成多态基类，并且可能通过基类指针删除对象，析构函数就应该声明为 virtual。

### 15. 构造函数能不能是虚函数？析构函数能不能是虚函数？

虚函数：对象已经存在，运行时决定调用哪个实现；构造函数：对象还在建立，必须先静态决定构造哪个具体类型，因此构造函数不能是虚函数；而析构函数可以是虚函数，因为析构时对象的动态类型已经确定，正需要通过基类指针正确销毁派生类对象。

补充：

> 构造和析构过程中调用虚函数也要谨慎，因为此时动态绑定行为不会表现为完整派生类对象的行为。
> 1. 构造函数不能声明为 virtual，会直接编译错误。根本原因是虚函数机制和构造过程在逻辑上互相冲突，虚函数调用需要先有一个已经确定的动态类型。
> 2. 在 Base 构造函数中调用虚函数时，只会调用 Base::VirtualFunction()。
> 3. 在 Derived 构造函数中调用时，才会调用 Derived::VirtualFunction()。
> 4. 对象完全构造后，正常发生虚函数动态绑定。
> 5. 析构时先执行 Derived，再执行 Base，虚函数分派也随之退回。
> (待验证)在对象构造过程中，vptr会先指向基类的虚函数表，随后才指向派生类的虚函数表。如果构造函数是虚函数，调用时vptr尚未指向正确的表（派生类的虚函数表），无法实现动态绑定

### 16. unique_ptr、shared_ptr、weak_ptr 有什么区别？

| 智能指针 | 所有权语义 | 适用场景 |
|---|---|---|
| `unique_ptr` | 独占所有权，不可拷贝，可移动 | 单一 owner，资源生命周期清晰 |
| `shared_ptr` | 共享所有权，引用计数 | 多个对象共享资源生命周期 |
| `weak_ptr` | 弱引用，不增加引用计数 | 观察 shared_ptr 管理对象，打破循环引用 |

面试表达：

> 默认优先考虑 unique_ptr，因为所有权最清晰。确实需要共享生命周期时再用 shared_ptr。出现双向引用、缓存观察对象等场景时，用 weak_ptr 避免循环引用。

### 17. 什么是 shared_ptr 循环引用？如何解决？

循环引用是指两个或多个对象通过 `shared_ptr` 互相持有，形成一个引用闭环。例如：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "Node destroyed\n"; }
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->next = a;
```

此时 `a` 和 `b` 的外部 `shared_ptr` 离开作用域后，各自的引用计数都只会从 2 降到 1，仍然被对方成员持有，引用计数无法归零，析构函数不会执行，最终造成内存泄漏。

解决方式是：只让真正拥有对象的一方使用 `shared_ptr`，观察关系或反向关系使用 `weak_ptr`：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->prev = a;
```

访问 `weak_ptr` 指向的对象时，需要先调用 `lock()` 获取临时的 `shared_ptr`，并判断对象是否仍然存在：

```cpp
if (auto prev = b->prev.lock()) {
    // prev 有效时才访问对象
}
```

面试表达：

> 循环引用的本质是所有权关系形成闭环，导致引用计数永远无法归零，进而导致管理的对象无法释放。解决时要区分“拥有关系”和“观察关系”：拥有关系用 `shared_ptr`，观察关系用 `weak_ptr`。常见场景包括双向链表、树的父子关系、对象回调和异步任务。

### 18. shared_ptr 的线程安全怎么理解？

`shared_ptr` 控制块中的引用计数增减（原子操作）通常是线程安全的，也就是多个 shared_ptr 实例在不同线程拷贝、析构不会破坏引用计数。

但要注意：

> shared_ptr 管理的对象本身不是自动线程安全的。多个线程同时读写对象内容，仍然需要锁或其他同步机制。同一个 shared_ptr 对象本身被多个线程同时读写，也需要额外同步。

### 19. 左值、右值、右值引用和移动语义是什么？

左值通常有稳定地址，可以出现在赋值号左边；右值通常是临时对象或即将销毁的值。右值引用用 `T&&` 表示，可以绑定右值。

移动语义的目的：

> 避免不必要的深拷贝，把临时对象或不再使用对象持有的资源直接转移给新对象，提高性能。

`std::move` 的作用：

> `std::move` 本身不移动资源，它只是把对象转换成右值引用，真正移动发生在移动构造或移动赋值函数里。

## P1：高频进阶，能体现工程能力

### 20. vector 和 list 有什么区别？

`vector` 动态数组，底层是堆上分配的连续内存，支持按照索引进行随机访问 O(1)，尾插通常高效，但中间插入删除需要移动后面元素 O(n)，扩容会导致迭代器、指针、引用失效。

`list` 底层是双向链表，其中元素通过指向前一个和后一个元素的指针进行链接,不支持随机访问 O(n)，插入删除节点本身高效且迭代器更稳定 O(1)，但内存不连续，缓存局部性差，额外指针开销大。

面试表达：

> 如果主要随机访问和尾部追加，用 vector；如果频繁在中间插入删除且已持有节点位置，可考虑 list。但现代 CPU 下 vector 的缓存友好性很好，很多场景即使有少量移动也比 list 快。
**vector是可以动态扩展的数组**，其底层是通过在堆中分配一段连续的内存空间实现。
+ 支持快速的随机访问，可以通过索引快速访问指定元素。同时使用连续内存分配可以利用缓存的优势，提高访问速度。
+ 因为是连续存储，所以没有使用额外的空间来保存指针或引用。
+ vector常用操作的时间复杂度：元素访问的时间复杂度是O(1)常数时间复杂度；在末尾插入或删除元素的时间复杂度是O(1)，在中间插入或删除元素的时间复杂度是O(n)，因为需要移动后续的所有元素。
+ vector的扩容机制：当要插入新元素时，发现将超出数组的容量，则需要进行扩容。申请重新分配一段更大的连续内存并将原有元素复制到新的内存空间。
**list是双向链表**，其底层是不连续的内存。
+ 因为不是连续存储，所以每个元素使用指向前一个和后一个元素的指针来链接元素，访问特定元素时需要从头开始进行遍历直到找到要访问的元素。
+ list常用操作的时间复杂度：元素访问的时间复杂度是O(n)，因为需要从头开始遍历到所访问的元素；插入和删除元素的操作是O(1)，但前提是已拥有指向待插入或删除元素的迭代器，这里不包含遍历的时间复杂度。

### 21. map 和 unordered_map 有什么区别？

`map` 通常基于红黑树，元素是键值对，且键唯一、不能重复，按照键保持有序，查找/插入/删除复杂度 O(logN)；`unordered_map` 基于哈希表，使用哈希函数将键映射到数组的索引，无序，查询、插入、删除**平均** O(1)，最坏可能退化为 O(n)。

面试表达：

> 需要有序遍历、范围查询、稳定的最坏复杂度时用 map；追求平均查找性能、无序即可时用 unordered_map。unordered_map 要关注哈希函数、冲突、扩容和内存占用。
在C++标准模板库（STL）中，map和unordered_map是两种关联容器，它们都用于存储键值对，但它们之间存在一些区别。
1. **首先说一下std::map：**
+ map是基于一种自平衡的二叉搜索树（通常是红黑树）来实现的，可以保持元素有序。元素按照键的大小进行排序，默认升序。
+ map的元素类型必须是键值对，并且键必须唯一，不能重复。
+ map提供元素的快速查找、插入、删除等操作，时间复杂度为O(log n)。
+ 由于基于树结构，迭代器在遍历时是稳定的，即使容器发生插入或删除操作，迭代器指向的元素也不会改变，除非该元素被删除。
2. **那么std::unordered_map:**
+ 是基于哈希表实现的，提供哈希函数将键分布到数组的槽位里。
+ unordered_map内部的元素是无序的，所以无法提供键的顺序进行遍历。在理想情况下，unordered_map进行元素快速查找、插入和删除操作的时间复杂度是O(1)。最坏的情况是性能下降到O(n)。
+ 由于是基于哈希表实现，所以unordered_map的迭代器的稳定性不如std::map。在发生哈希表的重新哈希时，迭代器可能会失效。
+ 遍历顺序与创建该容器时输入元素的顺序是不一定一致的，遍历是按照哈希表从前往后依次遍历的。
3. **总结一下区别：**
+ map基于红黑树实现，保持有序；unordered_map基于哈希表实现，无序；
+ map进行元素的快速查找、插入、删除等操作的时间复杂度为O(log n)。unorder_map进行元素的快速查询、插入、删除操作的平均时间复杂度是O(1)。但这些操作的时间复杂度可能会上升到O(n)，因为unordered_map是基于哈希表实现的，而哈希表的性能受到哈希函数的影响。当哈希函数将大量元素映射到同一个哈希桶时，会导致哈希冲突。在最坏的情况下，所有元素都被映射到同一个哈希桶，此时哈希表已经退化为一个链表。在这种情况下，查找、插入和删除操作都需要遍历整个哈希桶，而哈希桶的大小等于元素的数量。

### 22. 迭代器失效有哪些场景？

常见场景：

- `vector` 扩容后，所有迭代器、指针、引用都可能失效
- `vector` 中间插入/删除后，操作位置及其后的迭代器可能失效
- `deque` 插入删除可能导致迭代器失效
- `map/list` 删除某个元素，只会使被删除元素的迭代器失效
- `unordered_map` rehash 后迭代器可能失效

避免方式：

> 遍历中删除要使用容器返回的新迭代器；vector 提前 reserve **预分配内存**；不要长期保存可能失效的迭代器或元素地址。

### 23. vector 扩容机制是什么？

当 `vector` 容量不足时，会申请一块更大的连续内存，把原元素移动或拷贝过去，再释放旧内存。扩容倍率由实现决定，常见是 1.5 倍或 2 倍。

面试表达：

> 扩容会带来元素迁移成本，也会导致原迭代器、指针、引用失效。如果能预估大小，应使用 `reserve` 减少扩容次数。

### 24. 线程安全是什么？

线程安全是指多个线程并发访问同一段代码或同一份数据时，不会因为执行顺序不确定而产生错误结果、数据竞争或未定义行为。

实现方式：

- 避免共享可变状态
- 互斥锁（mutex）使用互斥锁保护临界区 （lock_guard/unique_lock 自动管理互斥锁）
- 条件变量（condition_variable）：允许线程等待某个条件成立，其他线程可以使用notify_one()或notify_all()通知条件已改变。
- 读写锁（shared_mutex）：允许多个线程同时读取共享数据，但在写入数据时只允许一个线程操作，适用于读多写少的场景。
- 信号量（counting_semaphore）：C++20 引入，可以限制同时访问某一资源的最大线程数。
- 使用原子变量（atomic）：利用底层的CAS（Compare-And-Swap）操作来确保数据的原子性操作，常用于实现无锁的线程安全编程。
- 使用线程局部存储（thread_local）：为每个线程提供独立的变量副本，从而实现线程间的数据隔离

面试表达：

> 多线程问题的核心不是线程本身，而是共享可变数据。只要有共享写，就要考虑同步或重新设计数据归属。

### 25. mutex 和 condition_variable 如何配合？

`mutex` 用来保护共享数据，`condition_variable` 用来等待某个条件成立并唤醒线程。典型场景是生产者消费者。

关键点：

> 条件变量等待时要配合锁，并且要用 while 或带谓词的 wait 检查条件，防止虚假唤醒。

表达示例：

```cpp
std::unique_lock<std::mutex> lock(mtx);
cv.wait(lock, [] { return !queue.empty(); });
```

### 26. 什么是死锁？如何避免？

死锁是多个线程或进程互相等待对方持有的资源，导致都无法继续执行。

四个必要条件：

1. 互斥
2. 持有并等待
3. 不可抢占
4. 循环等待

常见情况：运行到 unlock() 之前，可能就因为某些原因导致函数异常结束或提前退出，而锁一直没有解开，导致了死锁。

避免方式：

> 固定加锁顺序，减少锁嵌套，使用 `std::lock` 同时加锁，使用 RAII 自动释放锁，使用超时锁，避免持锁做耗时 IO 或回调外部代码。
> lock_guard的时候调用构造函数加锁，离开定义域时调用析构函数解锁，缺点是定义域范围越大则锁的粒度越大，不支持中途解锁。unique_lock 同样是 RAII 范式，但**支持 unlock() 中途手动解锁**，析构时会自动根据锁状态决定是否释放锁。
> lockguard想缩短它的粒度的话，用 {} 创建一个域
> 粒度大的锁主打安全可靠，可以覆盖复杂逻辑，适合用在可靠性要求高但速度要求不高的代码，比如界面编程，界面操作速度又不快。粒度小的锁主打高性能+高可靠，适合性能要求高同时逻辑不能太复杂的场景比如多线程对缓存读写，锁定的范围只有线程放数据/取数据，缓存操作完毕之后立刻释放锁，数据的处理放在锁定的范围之外处理

### 27. 线程池的基本结构是什么？

线程池通常包含：

- 固定或动态数量的工作线程
- 任务队列
- 互斥锁和条件变量
- 提交任务接口
- 停止标志和优雅退出逻辑

面试表达：

> 线程池的价值是复用线程，避免频繁创建销毁线程的开销，并通过队列控制并发度。设计时要关注任务队列容量、拒绝策略、异常处理、停止流程和任务执行时间过长的问题。
> 线程池解决的是线程生命周期成本和并发度控制问题，适合IO密集型中小并发、资源受限场景。
> 协程池解决的是线程阻塞浪费CPU和高并发受限问题，适合高并发IO密集型、资源受限但并发需求高的场景。

### 28. 宏和 inline 函数有什么区别？

宏由预处理器做文本替换，没有类型检查，容易产生副作用；`inline` 是函数，在编译时执行，将实现直接在调用处展开，取消函数的参数压栈、函数返回步骤，有类型检查、作用域和调试信息，是否真正内联由编译器决定，用于小型且频繁调用的函数。

面试表达：

> 能用 constexpr、inline、模板、枚举解决的问题，尽量不用宏。宏适合条件编译、平台差异和少量编译期控制。
> constexpr:语义是编译期常量，编译时即确认为常量

### 29. C++ 类型转换有哪些？

| 转换 | 用途 |
|---|---|
| `static_cast` | 相关类型之间的明确转换，如数值、基类/派生类静态转换 |
| `dynamic_cast` | 多态类型安全向下转换，运行期检查，若转换合法，则返回目标类型的指针或引用；否则返回空指针（对指针转换）或抛出 std::bad_cast异常（对引用转换） |
| `const_cast` | 去掉或添加 const/volatile |
| `reinterpret_cast` | 低层次二进制解释转换，风险高 |

面试表达：

> C++ 风格转换比 C 风格强制转换更明确，能表达转换意图。工程上应尽量避免 reinterpret_cast，除非是底层系统或序列化等明确场景。
> volatile:（确保多线程下的）可见性与指令有序性，告诉编译器该变量的值可能由编译器无法预见的因素（如硬件、中断、其他线程）改变，因此每次访问都必须从内存中读取，不能缓存到寄存器

### 30. 模板为什么通常写在头文件？

模板不是普通函数或类，允许以通用的方式定义可以适用于不同数据类型的类和函数。编译器需要在使用点看到模板定义，才能根据具体类型实例化代码。如果只把模板定义放在 cpp 文件，其他翻译单元使用时可能无法实例化，导致链接错误。

面试表达：

> 模板的本质是编译期代码生成，声明不够，使用处通常必须能看到完整定义。

### 32. class 和 struct 有什么区别？

在C++中，class和struct在功能上几乎没有区别，都可以定义复杂的数据类型，包含成员变量和成员函数，并支持封装、继承和多态等面向对象的特性。主要区别是默认访问权限不同：`class` 默认 private，`struct` 默认 public。默认继承权限也不同：class 默认 private 继承，struct 默认 public 继承。

## C++11/14/17/20 特性专题答案

下面的内容用于补充版本特性题。回答时建议按“特性是什么、解决什么问题、使用时有什么边界、项目中如何选择”展开，避免只罗列标准新增名词。

### 33. C++11 相比 C++03 主要改进了什么？

C++11 是现代 C++ 的基础版本，重点解决了资源管理、类型推导、函数对象和并发编程中的重复代码与性能问题。高频特性包括：

- `auto`、`decltype`、`nullptr`、范围 `for`、统一初始化和 `enum class`
- Lambda、右值引用、移动语义和完美转发
- `= default`、`= delete`、`override`、`final`、`noexcept`
- `unique_ptr`、`shared_ptr`、`weak_ptr` 和 RAII
- `thread`、`mutex`、`condition_variable`、`future`、`atomic`
- `unordered_map`、`array`、`tuple`、`function`、随机数库和时间库

面试表达：

> C++11 的核心价值是把资源管理和类型表达能力交给语言与标准库。移动语义减少了不必要的深拷贝，智能指针和 RAII 降低了资源泄漏风险，Lambda 和标准线程库让函数式回调与并发编程更直接。

### 34. `auto`、`decltype` 和 `nullptr` 如何使用？

`auto` 根据初始化表达式推导变量类型，但会像模板参数推导一样忽略顶层 `const` 和引用；如果希望保留引用，需要显式写 `auto&` 或 `auto&&`。`decltype` 根据表达式的形式推导类型：未加括号的变量名得到声明类型，带括号的左值表达式通常得到引用类型。

```cpp
const int value = 1;
auto a = value;       // int
decltype(value) b = 2;// const int
decltype((value)) c = value; // const int&
```

`nullptr` 是 `std::nullptr_t` 类型的空指针字面量，可以转换为任意指针类型；`NULL` 在很多实现中只是整数 `0`，传给重载函数时可能产生歧义。

面试陷阱：

> `auto` 不是“动态类型”，类型在编译期已经确定；使用 `auto` 时仍要关注值拷贝、引用和 `const` 是否被保留。`decltype(auto)` 适合需要精确保留返回值引用属性的场景，但也可能把局部变量引用返回出去形成悬空引用。

### 35. Lambda 的捕获方式和生命周期风险是什么？

Lambda 本质上是一个编译器生成的函数对象。`[x]` 按值捕获，`[&x]` 按引用捕获，`[=]` 和 `[&]` 分别表示默认按值或按引用捕获，`[this]` 捕获当前对象指针。

```cpp
int value = 1;
auto by_value = [value] { return value; };
auto by_ref = [&value] { return value; };
auto moved = [ptr = std::make_unique<int>(1)] {
    return *ptr;
};
```

常见风险：

- 异步任务按引用捕获局部变量，任务执行时局部变量可能已经销毁
- 捕获 `this` 只复制指针，不延长对象生命周期
- 按值捕获大型对象会产生拷贝，必要时应考虑移动捕获或引用捕获
- `mutable` 可以修改 Lambda 内部保存的值，但不会修改外部原变量

面试表达：

> Lambda 的关键不是语法简洁，而是捕获对象的所有权和生命周期必须明确。异步回调中，如果需要延长对象生命周期，应捕获合适的 `shared_ptr`；如果只是观察对象，则要保证任务执行期间对象一定有效，不能盲目捕获 `this`。

### 36. 移动语义、完美转发和 `noexcept` 有什么关系？

移动语义通过右值引用接管临时对象或即将销毁对象的资源，避免重新分配和深拷贝。`std::move` 只是类型转换，不会自己移动资源；真正的移动发生在移动构造或移动赋值函数中。`std::forward<T>` 用于模板中保持参数原本的左值/右值属性。

```cpp
template <class T, class... Args>
std::unique_ptr<T> make(Args&&... args) {
    return std::make_unique<T>(std::forward<Args>(args)...);
}
```

移动构造和移动赋值通常应声明为 `noexcept`。因为 `vector` 扩容时需要保证异常安全：如果移动可能抛异常，容器通常会选择拷贝；如果移动是 `noexcept`，容器可以安全地优先移动元素。

面试表达：

> 移动语义优化的是资源所有权转移，而不是简单地把所有成员“复制得更快”。移动后的对象必须仍处于有效但未指定的状态，不能继续假设其原有内容。只有确认移动操作不会抛异常时，才应声明 `noexcept`，不能为了触发优化而虚假标注。

### 37. C++14 增加了哪些高频特性？

C++14 主要是对 C++11 的补强，降低现代写法的使用成本：

- 泛型 Lambda：参数可以写成 `auto`，同一个 Lambda 可处理多种类型
- Lambda 初始化捕获：可以在捕获列表中声明并初始化新变量
- 更宽松的 `constexpr`：允许局部变量和多条语句
- 函数返回类型推导：适合简单函数，但复杂重载接口仍建议显式返回类型
- `std::make_unique`：以异常安全的方式创建 `unique_ptr`
- 二进制字面量、数字分隔符、变量模板

```cpp
auto add = [](auto left, auto right) {
    return left + right;
};

auto resource = std::make_unique<int>(42);
auto callback = [resource = std::move(resource)] {
    return *resource;
};
```

面试表达：

> C++14 没有改变 C++11 的核心模型，主要让泛型 Lambda、移动捕获和编译期计算更实用。初始化捕获尤其适合把不可拷贝资源移动进异步任务或回调对象中。

### 38. C++17 的结构化绑定、`if constexpr` 和 CTAD 解决什么问题？

结构化绑定可以直接解包 `pair`、`tuple`、数组或提供绑定接口的类型；`if constexpr` 在编译期选择分支，被丢弃的分支不会参与实例化；CTAD 允许编译器从构造函数参数推导类模板参数。

```cpp
auto [name, score] = std::pair<std::string, int>{"cpp", 95};

template <class T>
void print(T value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << value << " is integer\n";
    } else {
        std::cout << value << " is not integer\n";
    }
}

std::pair result{"cpp", 95}; // CTAD 推导为 pair<const char*, int>
```

面试陷阱：

> 结构化绑定默认可能发生拷贝，需要修改原对象时使用 `auto&` 或 `const auto&`。`if constexpr` 是编译期分支，不等同于运行期 `if`。CTAD 可能推导出与预期不同的类型，例如字符串字面量会推导为 `const char*`，应在接口边界处显式写出类型。

### 39. `optional`、`variant`、`any` 和 `string_view` 如何选择？

| 类型 | 语义 | 主要风险或代价 |
|---|---|---|
| `std::optional<T>` | 可能存在一个 `T` | 忘记判断 `has_value()` 或错误使用 `value()` 抛异常 |
| `std::variant<T...>` | 若干候选类型中的一个 | 访问前要判断类型，通常使用 `std::visit` |
| `std::any` | 运行期保存任意类型 | 类型约束弱、可能有类型擦除和分配开销 |
| `std::string_view` | 指向字符序列的非拥有视图 | 原字符串销毁或移动后，视图可能悬空 |

```cpp
std::optional<int> find_id();
std::variant<int, std::string> result;
std::string text = "hello";
std::string_view view = text; // view 不拥有 text
```

面试表达：

> `optional` 表达“有或没有”，`variant` 表达“几种明确类型中的一种”，`any` 表达“类型运行期才知道”。能用前两者表达清楚时，不要用 `any` 牺牲类型安全。`string_view` 适合只读参数和解析窗口，但不能返回指向局部字符串的视图，也不能默认它以空字符结尾。

### 40. C++17 的 `filesystem`、`constexpr` 和标准属性有什么价值？

`std::filesystem` 统一了路径、目录、文件状态和文件操作；C++17 进一步放宽了 `constexpr`，让更多算法和数据结构能够在编译期计算；`[[nodiscard]]` 可以提醒调用方不能忽略返回值，`[[maybe_unused]]` 和 `[[fallthrough]]` 用于表达明确意图。

```cpp
[[nodiscard]] bool save_config(const std::filesystem::path& path);

if (std::filesystem::exists("config.json")) {
    // 继续读取配置
}
```

面试时要补充：`filesystem` 的操作可能失败，应检查错误码或捕获 `filesystem_error`；属性是给编译器和读代码的人看的约束提示，不能替代运行时校验。

### 41. C++20 Concepts 和 `requires` 解决了什么问题？

Concepts 用可读的约束描述模板参数必须满足的条件，让错误更早、更接近调用点，也避免大量依赖 SFINAE 的复杂写法。

```cpp
template <typename T>
concept Addable = requires(T left, T right) {
    { left + right } -> std::convertible_to<T>;
};

template <Addable T>
T add(T left, T right) {
    return left + right;
}
```

`requires` 可以出现在模板参数、函数尾部或表达式中，用于检查类型是否支持某个操作。Concepts 约束的是编译期类型关系，不会在运行期做类型检查，也不会自动解决算法复杂度或生命周期问题。

面试表达：

> Concepts 的价值是把模板的隐式要求显式化，让接口契约和编译错误更清晰。它改善的是模板可读性和诊断能力，不代表模板代码就没有运行时开销，也不代表任意类型都应被放宽为通用模板。

### 42. C++20 的 `<=>`、`consteval` 和 `constinit` 有什么区别？

`<=>` 是三路比较运算符，可以一次产生小于、等于或大于的比较结果，并在适当情况下自动生成其他比较运算符。`constexpr` 函数可以在编译期或运行期执行；`consteval` 函数必须在编译期执行；`constinit` 用于要求具有静态存储期的变量进行静态初始化，但变量本身不一定是 const。

```cpp
struct Version {
    int major;
    int minor;
    auto operator<=>(const Version&) const = default;
};

consteval int compile_only() { return 2020; }
constinit int version = compile_only();
```

面试表达：

> `constexpr` 是“可以编译期求值”，`consteval` 是“必须编译期求值”，`constinit` 是“静态对象必须完成静态初始化”。三者关注点分别是求值时机、强制求值和初始化阶段。

### 43. `span`、Ranges 和协程分别解决什么问题？

- `std::span<T>` 是连续内存的非拥有视图，把指针和长度组合成一个参数，适合接收数组、`vector` 或其他连续容器；调用方必须保证底层数据在 `span` 使用期间有效。
- `std::ranges` 提供带约束的算法和惰性视图，可以用管道组合过滤、转换等操作；视图通常不拥有数据，迭代时仍需保证源数据有效。
- 协程通过 `co_await`、`co_yield`、`co_return` 描述可挂起函数，编译器会生成保存局部状态的状态机。协程本身不等于线程，是否异步以及由谁调度取决于协程返回类型和执行器设计。

```cpp
void consume(std::span<const int> values);

auto even = numbers
    | std::views::filter([](int value) { return value % 2 == 0; })
    | std::views::transform([](int value) { return value * 2; });
```

面试陷阱：

> `span` 和 ranges view 都是非拥有对象，不能脱离底层容器生命周期使用。协程降低了异步流程的表达复杂度，但会引入协程帧、挂起点和销毁时机等生命周期问题，生产代码必须明确取消、异常传播和执行线程。

### 44. `jthread`、`stop_token`、信号量、闩锁和屏障怎么选？

`std::jthread` 析构时会自动请求停止并等待线程结束，相比 `std::thread` 更不容易因为忘记 `join()` 触发问题；但停止是协作式的，线程函数必须检查 `stop_token` 或响应停止回调，系统不能强制安全地终止任意线程。

- `counting_semaphore`：控制同时进入某类资源的线程数量
- `latch`：一次性等待固定数量的任务完成
- `barrier`：多个阶段重复等待，所有参与者到达后进入下一阶段

面试表达：

> 这些 C++20 同步工具表达的是不同的同步协议：信号量控制资源计数，闩锁等待一次性事件，屏障协调重复阶段。选择时先描述线程之间的关系，再选择对应工具，不能只因为 API 更新就替换所有 mutex 和条件变量。

### 45. 如何在面试中比较 C++11、14、17、20？

可以用下面的主线回答：

> C++11 建立现代 C++ 的基础，重点是移动语义、Lambda、智能指针、类型推导和标准并发库；C++14 对 C++11 做易用性补强，代表特性是泛型 Lambda、初始化捕获和 `make_unique`；C++17 强化编译期编程和类型安全，代表特性是结构化绑定、`if constexpr`、`optional`、`variant`、`string_view` 和 `filesystem`；C++20 则进一步改善模板约束、范围处理、协程和并发同步，代表特性是 Concepts、Ranges、Coroutines、`jthread`、`span` 和 `<=>`。
>
> 工程上不能只看标准版本，还要确认编译器、标准库和构建链的支持程度。选择特性时要同时考虑可读性、异常安全、对象生命周期、性能测量和团队编译环境。
