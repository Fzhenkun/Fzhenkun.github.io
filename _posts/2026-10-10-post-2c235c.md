## 1. 目标与约束

| 项 | 要求 |
|---|---|
| 快 | 1 天内上线;写作只需 `.md` 文件 + `git push` |
| 简洁 | 阅读体验优先,无后台、无数据库、无多余功能 |
| 免租服务器 | 纯静态站点,托管在 GitHub Pages(免费、HTTPS、自带 CDN) |
| 内容类型 | 技术文章:代码高亮、图片、数学公式、目录(TOC)、搜索 |
| 环境 | Windows;Git 已有 |

## 2. 参考站点技术拆解

| | BOT Man JL | Tech Learning Notes (xirain) |
|---|---|---|
| 生成方式 | **无构建**:浏览器端用 `marked.js` 实时渲染 `.md` | **Jekyll 4.4 + Chirpy 主题**(静态预构建) |
| 公式/代码 | KaTeX / highlight.js(前端加载) | 主题内置高亮;CDN 加载 tocbot、glightbox、FontAwesome |
| 导航/功能 | 极简单页:标题、目录、分享二维码、打印样式 | 侧栏、分类、标签、归档、关于、搜索、明暗主题、Catppuccin 配色 |
| 托管 | GitHub Pages | GitHub Pages(项目站,baseurl `/techlearn`) |
| 优点 | 零工具链,写完即发 | 功能完整、SEO 好、首屏即 HTML |
| 缺点 | 首屏依赖 JS;SEO 差;URL 用 `?post=` | 需 Ruby/Jekyll(可交给 CI) |

## 3. 方案选型

**方案 A(推荐)—— Jekyll + Chirpy,GitHub Pages + Actions 自动构建**
- 与参考站 2 一致,成熟、功能齐全,SEO 与搜索开箱即用。
- 使用官方 `chirpy-starter` 模板:**本机无需安装 Ruby**,push 后由 GitHub Actions 构建部署。
- 需要本地预览时再装 Ruby+DevInstaller,或使用 Docker/WSL(可选)。

**方案 B(备选)—— 仿参考站 1 的“零构建”前端渲染**
- 一个 `index.html` + `marked.js` + highlight.js + KaTeX,文章为 `posts/*.md` + `posts.json` 索引。
- 极致轻量,但 SEO/分享预览差,需自写目录、搜索、路由。

**方案 C(备选)—— VitePress / Hexo**(skill 自带模板,Node 技术栈)
- 若不想碰 Ruby,可选 VitePress(偏文档站)。博客风格弱于 Chirpy。

> 说明:skill 默认推荐 Hexo,但你明确偏好参考站方案,故首选 A;B 作为“最简”后备。

## 4. 推荐方案 A 详细设计

### 4.1 仓库与域名
- 仓库名 `<GitHub用户名>.github.io` → 站点 `https://<用户名>.github.io/`(推荐,无 baseurl 烦恼)。
- 之后可绑定自有域名(CNAME,可选,约 ¥50–70/年;非必需)。

### 4.2 目录结构
```
<user>.github.io/
├─ _config.yml          # 站点标题、描述、作者、url、语言(zh-CN)、时区(Asia/Shanghai)
├─ _posts/              # YYYY-MM-DD-slug.md
├─ _tabs/               # about / archives / categories / tags
├─ assets/img/          # 头像、文章图片(按文章分目录)
├─ .github/workflows/   # pages-deploy.yml(starter 自带)
├─ Gemfile
└─ PLAN.md              # 本文档(可不提交)
```

### 4.3 文章规范(Front Matter)
```yaml
---
title: 文章标题
date: 2026-10-10 21:00:00 +0800
categories: [C++, 编译优化]    # 最多两级
tags: [cpp, build]
math: true                    # 需要公式时开启
mermaid: true                 # 需要流程图时开启
---
```
- 图片:`assets/img/posts/<slug>/xxx.png`,提交前压缩(squoosh / `optimize-images.sh`)。
- 分类仅 1–2 级,标签小写英文,避免膨胀。

### 4.4 功能清单(P0 必须 / P1 增强)
| 优先级 | 功能 | 实现 |
|---|---|---|
| P0 | 代码高亮、复制按钮、TOC | Chirpy 内置 |
| P0 | 分类/标签/归档/关于 | `_tabs` |
| P0 | 明暗主题 | Chirpy 内置 |
| P0 | 站内搜索 | Chirpy 内置(simple-jekyll-search) |
| P0 | RSS、sitemap、SEO meta | jekyll-feed / seo-tag(内置) |
| P1 | 评论 | giscus(基于 GitHub Discussions,免费,无需服务器) |
| P1 | 访问统计 | Cloudflare Web Analytics / GoatCounter(免费、隐私友好) |
| P1 | 数学公式 | `math: true`(MathJax) |
| P1 | 图片灯箱 | glightbox(内置) |
| P2 | 自定义配色(如 Catppuccin) | 覆盖 `assets/css/jekyll-theme-chirpy.scss` |

### 4.5 简洁性原则
- 仅保留:首页列表、文章页、分类、标签、归档、关于。
- 不引入评论以外的第三方脚本;字体使用系统字体或单一 Google Fonts(国内可能慢,可改用自托管/jsDelivr)。
- 不做自建后台、不做多语言(后续需要再加)。

### 4.6 部署流程(全自动)
1. 创建仓库 `<user>.github.io`(基于 Chirpy Starter 模板)。
2. 仓库 Settings → Pages → Source 选 **GitHub Actions**。
3. 修改 `_config.yml`(title/tagline/url/github.username/avatar/lang/timezone)。
4. `git push` → Actions 构建 → 约 1–3 分钟上线。
5. 日常发文:新增 `_posts/*.md` → commit → push。

### 4.7 本地预览(可选)
- 推荐:不装环境,直接 push 看线上(分支预览不可用时用草稿 `_drafts/`)。
- 需要本地时:安装 RubyInstaller(含 DevKit)→ `bundle install` → `bundle exec jekyll s -l`(访问 `localhost:4000`)。
- 或 Docker:`docker run -p 4000:4000 -v ${PWD}:/srv/jekyll jekyll/jekyll jekyll s`。

## 5. 实施计划

| 阶段 | 内容 | 产出 | 预估 |
|---|---|---|---|
| M0 | 确认方案与基础信息(见第 7 节) | 定稿 | 10 min |
| M1 | 生成项目骨架(chirpy-starter),填写配置 | 可构建仓库 | 30 min |
| M2 | 推送 GitHub,启用 Pages Actions,上线 | 公网 URL | 30 min |
| M3 | 配置头像、关于页、分类/标签,写 1–2 篇样例文章(含代码/图/公式) | 内容就绪 | 1 h |
| M4 | P1:giscus 评论、统计、图片压缩流程 | 增强完成 | 1 h |
| M5 | 验收:Lighthouse、移动端、RSS、搜索 | 验收清单通过 | 30 min |

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 国内访问 `github.io` 偶尔慢/不稳 | 接受;或加 Cloudflare Pages 镜像 / 绑定域名走国内 CDN(需备案考量) |
| Google Fonts / jsDelivr 在国内较慢 | 字体自托管;CDN 换 `cdn.bootcdn.net` 或本地化 |
| Ruby 在 Windows 安装繁琐 | 默认走 Actions 构建,不强制本地装 |
| Chirpy 升级导致样式覆盖失效 | 用 gem 版主题 + 少量覆盖,锁定版本 |
| 仓库公开,草稿泄露 | 草稿放本地或私有分支,不提交 |
| 图片拖慢首屏 | 提交前压缩,`loading=lazy`(主题默认) |

## 7. 待你确认的信息

1. 方案:**A(Chirpy,推荐)** / B(零构建) / C(VitePress)?
2. 网站名称、一句话描述(如“记录技术成长的每一步”)。
3. 作者名(留空则使用占位符“你的名字”)。
4. GitHub 用户名(决定域名;是否已有账号与 `gh` CLI/登录?)。
5. 项目本地目录:默认 `d:\projects\Personal_blog_website\blog\`。
6. 是否需要:评论(giscus)、访问统计、数学公式、自定义域名?
7. 是否本地预览(需装 Ruby),还是仅线上预览?

## 8. 验收标准
- 公网 HTTPS 可访问,首页/文章/分类/标签/归档/关于均正常。
- 文章含代码高亮、图片、公式(如启用)渲染正确;搜索可用。
- 手机端排版正常;Lighthouse Performance ≥ 90、SEO ≥ 95。
- 新增文章仅需“新建 md → push”,3 分钟内上线。
